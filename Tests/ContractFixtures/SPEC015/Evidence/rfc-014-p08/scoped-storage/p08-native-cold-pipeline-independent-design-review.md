## Preservation and feasibility checks

- **Explicit facts borrows:** replacing captured mutable accumulation with an
  equivalent noncapturing helper/ordinal traversal can give the compiler a static
  exclusive borrow without disabling runtime enforcement. Retain row/order,
  arithmetic/preconditions, actual original-field borrows and every reset/reentry/
  overlap outcome. A surviving required dynamic access remains enabled and is a
  strict cold-screen failure if it allocates TLS; preinitializing TLS is forbidden.
- **Specialization:** targeted serialized/always-inline entry and forwarding bodies
  may retain the existing generic operation algorithms. Recursive traversal must
  remain the same recursive visitor, with concrete specialization of its witness/
  role/read/binding chain, not infinite inlining, flattened expansion or a second
  traversal. Whether Swift6.4 `-Osize` emits that monomorphic recursion is genuinely
  unproved. A missed emitted edge is a feasibility failure to report, not evidence
  that a different compiler policy or normative API change is already necessary.
- **Generated payload owner:** private nongeneric UInt8-field owners can replace
  tuple ownership internally. `withUnsafeBytes` and exact byte-count checks remain;
  no tuple cast, field-offset assumption or relaxed mismatch path is permitted.
  Check every generated record byte, offset, ID, empty case, digest and asset pin
  against baseline through the generator. The public package/callback behavior
  and bitmap/outline selections remain identical. Concrete storage/metadata may
  still allocate or increase flash/stack; the design does not assume otherwise.
- **Raster and results:** pairwise scalar min/max is equivalent for the same pure
  geometry projections; preserve values/evaluation effects, overflow, empty and
  replacement refusal checks. Explicit result equality must compare every case
  and associated value in the same semantic order. These are implementation
  spellings, not new raster, scheduler or failure algorithms.
- **Capabilities and lifetime:** serialized checked operations may reference
  internal implementation helpers, but unchecked construction/provenance remains
  source-inaccessible. Retain all actual model/control/identity/report/storage
  borrows, read/mutation exclusion and private constructor/Optional dependencies.
  Preserve acquired-prefix reverse destruction, first failure, pins/claims,
  quiescence, once-only retirement and backing-last cleanup. No initialized old
  and new owner share a region. Requalify the existing candidate root/control split
  as part of the correction; compilation has not adopted it.
