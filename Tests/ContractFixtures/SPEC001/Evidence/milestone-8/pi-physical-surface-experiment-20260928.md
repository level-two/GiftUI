# Pi complete physical-surface experiment — 2026-09-28

This is an isolated cold/full-frame experiment on
`feature/pi-cold-full-surface-experiment`, based on the verified
`feature/pi-cold-frame-path` code. Commits `e807e330` and `6324fef2` add an
environment-selected prototype. No Specification or accepted architecture was
changed. The connected Raspberry Pi 1 reported `armv6l`; runs used a foreground
executable without restarting a service. The clean ARMv6 build of the physical
prototype had build ID `fa9552e193a74a57b35ca3e74b58c74731401430`.

## Pixel equivalence and ordering

The first prototype rasterized into a 240 × 240 logical RGB565 buffer and
submitted its projected rows. It did not match the selected tiled path. The
[tiled initial-frame hash](pi-full-surface-initial-tiled-sha256-20260928.txt)
was `71d77e0ed75235cd8172f8b311181ebd0830017df3c98698ae0cfc0830a412d3`
in two runs; the [logical-surface hash](pi-full-surface-initial-full-sha256-20260928.txt)
was `b369758582e2a8599c8aaf58108d4287fdd6c4eb79ddc18aea930fc274775913`.
On-board byte comparison located 2,986 changed physical pixels in 65 rows.
Those rows are a subset of the 160 overlapping rows generated by the current
240-to-320 vertical floor/ceiling projection. The selected path resolves
overlapping physical writes in operation order; a completed logical image
submitted in row order resolves them differently.

Commit `6324fef2` instead rasterizes operations directly into a 480 × 320
RGB565 physical buffer in operation order, then copies its 307,200 bytes to
the mapped framebuffer. Its [initial-frame hash](pi-physical-surface-initial-sha256-20260928.txt)
matches the tiled hash exactly. The [tiled](pi-full-surface-initial-tiled-20260928.log),
[logical-surface](pi-full-surface-initial-full-20260928.log), and
[physical-surface](pi-physical-surface-initial-20260928.log) one-frame logs
capture those runs. The initial tiled workload emitted 311 payloads, 3,577
regions, and 218,874 payload bytes. Initial physical-surface derivation and
offer took 258.112 and 260.481 ms, respectively; its internal raster and
mapped copy took 255.882 and 1.714 ms. These are separate initial runs and
exclude process startup and visible panel completion.

## Same-binary 60-second comparison

The [physical-surface run](pi-physical-surface-60s-20260928.log),
[tiled control](pi-physical-surface-tiled-60s-20260928.log), and
[physical-surface repeat](pi-physical-surface-repeat-60s-20260928.log) used
the same binary, with only `GIFTUI_PI_EXPERIMENT_FULL_SURFACE=1` selecting the
prototype. Each ran for 60 seconds with `GIFTUI_PI_TRACE=1`. All completed
normally. Means below use completed steady frames; the first `pi-present-us`
entry, which describes initial presentation, is excluded.

| Application phase | Physical (108 frames) | Tiled control (38 frames) | Physical repeat (110 frames) |
| --- | ---: | ---: | ---: |
| **Total frame service** | **537.817 ms** | **1,534.086 ms** | **527.917 ms** |
| Presentation derivation | 214.044 ms | 186.223 ms | 211.787 ms |
| Offer including sink | 321.017 ms | 1,345.219 ms | 313.488 ms |
| Raster inside physical offer | 317.918 ms | — | 310.319 ms |
| Physical mapped copy | 1.659 ms | — | 1.711 ms |
| Tiled framebuffer sink | — | 780.781 ms | — |

The prototype reduces observed complete-frame service by about 65% against
this tiled control. The physical runs span 466.364–554.990 ms and
452.610–546.773 ms, respectively. They remain about 2.1 times the 250 ms
target. Even with the mapped copy near 1.7 ms, measured derivation (~212–214
ms) plus raster (~310–318 ms) exceeds the target. Those are the next
cold-path costs to investigate.

## Contract and measurement limits

The prototype allocates a 307,200-byte offscreen physical image in addition
to the mapped framebuffer. It also bypasses the selected `DisplayTarget`
reserve/transfer path and its failure semantics. The extra full framebuffer
conflicts with SPEC-014 BI-006's selected resource bound. This branch is
experimental evidence, not a production implementation or approval to change
that contract. Its buffer is reused as an allocation, but each frame still
rasterizes the complete surface; no damage-delta or retained-content cache is
used. No Specification was modified.

The trace measures application frame service. It does not measure SPI
completion, panel visibility, or touch response. The physical copy timer does
not imply the panel can display at the same rate. The experiment had a clean
ARMv6 build and exact initial framebuffer comparison; the full host suite was
not rerun for this isolated prototype. The accepted production path had
previously passed 1,144 host tests with `-DGIFTUI_DYNAMIC_PROFILE` and its
exact Pi native raster gate.
