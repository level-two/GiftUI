## One grouped correction

Use one **concrete cold entry with specialized checked operations**, not a second
coordinator or generated expansion graph. Apply corrective1 as a reviewed overlay
on the current failed candidate; use
immutable baseline `93f6ecc7` to check semantic/layout differences, without a
restoration command. The existing concrete root/control/read-field representation
remains an unaccepted intermediate until the complete correction passes. Nothing
in the failed diff is adopted merely because it compiles. Requalify its physical
layout and the complete ownership path.

1. **Make exclusive access structural.** In physicalFacts, replace the nested
   mutating `object` capture with a noncapturing helper accepting
   `inout CounterPhysicalGeometryFacts` and explicit immutable inventory facts.
   Append in exactly the same order, retaining arithmetic/preconditions. Replace
   the captured totals update with an explicit bounded ordinal traversal or a
   helper borrowing the facts and receiving the totals as explicit `inout`.
   Borrow each original owner field for its whole checked callback; no new unsafe
   pointer alias, suppression or runtime-check removal. Inspect *all* reachable
   beginAccess sites after specialization, not just group0. If a selected cold
   path still requires dynamic enforcement, retain it and report failure; do not
   initialize TLS earlier.
2. **Require specialization at observed call edges.** Candidate1's `@inlinable`
   only made bodies available. At the mapped generic entry/forwarding seams,
   serialize the body and use targeted `@inline(__always)` where needed to move
   the operation into the already concrete caller. Serialize only directly
   referenced helpers/types/conformances; keep unchecked constructors module
   internal with their complete lifetime dependencies. Keep normal generic APIs.
   For recursive semantic traversal, expose its type, witness bodies, role query,
   state binding and nonrecursive entry so the compiler can emit a monomorphic
   recursive specialization; do not try to infinitely inline recursion, flatten
   the graph or substitute a hand-authored traversal. Concrete CounterRoles metatype
   tests should fold at the finite declaration call sites. A surviving runtime
   type lookup in a selected recursion is a failed feasibility gate.
3. **Avoid runtime metadata for owning byte shapes.** In the existing reference
   generator's payload emission, replace each tuple byte literal with a private
   nongeneric nominal byte owner (UInt8 fields, including an explicit empty case).
   Continue using checked `withUnsafeBytes(of:)`; never cast a tuple to contiguous
   storage or infer Swift layout. Keep its exact byte-count guard and verify every
   record byte, offset, ID and digest against the original payload. Serialize the
   `withRecordBytes`/`withPayload` chain and actual validator/raster callback so
   generic Result/Optional metadata is eliminated at the concrete call. Generated
   output changes come from the generator, not hand editing the data. This is a
   candidate realization, not proof that nominal storage alone cures metadata.
4. **Remove the scalar variadic seam.** Four-way max/min in raster intersection
   becomes pairwise two-way max/min over the same values, with the same evaluation
   order of pure geometry projections and unchanged overflow/empty checks. Actual
   code currently calls mangled-type instantiation then swift_initStackObject;
   the object need not itself be heap-backed for its first-use metadata to reject
   zero heap. Do not blame pixel storage or exclude this framework operation.
5. **Close result and teardown edges too.** Specialize activation/scheduler/
   pipeline/result handling, Optional extraction and byte-delivery callbacks.
   Where a synthesized generic Equatable operation cannot be serialized, an
   equivalent explicit case switch may implement its existing conformance; no
   case, associated comparison or first-failure check may disappear. Keep all
   source tests and counter counts. No dead-symbol-only zero-heap inference.

## Lifecycle, risks and focused acceptance

Representations remain typed/initialized at original addresses. Preserve partial
initialization's reverse-prefix destruction, model pins/claims, original14 loan
callbacks, nonescaping callback count, read/mutation exclusion, Optional host
lifetime union, quiescence and once-only retirement. No initialized old/new owner
may cover the same bytes. Shared owner/API changes require Dynamic as well as
Static positive twins; Embedded unaffectedness must be demonstrated, not assumed.
Specialization/nominal payloads can increase code/stack/static bytes, so all final
resource/ABI evidence becomes stale for affected owners; no numerical saving or
fit is promised here.

Before spending corrective1 on an actual run, prepare one bounded codegen screen
for *every row*, with exact source/module/compiler identities. First inspect
concrete emitted clones/recursive edges, no runtime metadata/conformance lookup
on the selected cold paths, no rooted allocation/TLS route hidden by helper calls,
and static access where claimed. A symbol remaining for Dynamic/unused generic
clients is not failure by itself. A missing positive allocation is not proof of
unobserved VM/temp/direct-zone routes either. Do not run full suites to explore
which row failed.

Then run the original fresh host-first cold/reuse and registered ordinary screen
once, with the immutable matching baseline/interface pair, same flags, no graph
prewarm, all exact counts and full-stack replay checks. Compile the existing
private-construction/escape/overlap positive twins and negative carrier/lifetime
controls; preserve runtime-exclusivity rejection where static proof is unavailable.
Exercise construction/activation failure, action/refusal, teardown and reconstruction
without exception or oracle weakening. Any actual selected-profile allocation is
failure; record it and consume the correction transparently. No broad collections
or images follow failure. If focused checks pass, collect the registered four
profiles, actual images, complete rooted allocation coverage, Native/Pi stack/
physical ledger, matched Dynamic overhead and independent exit review. Tests alone
do not close P08.

The immediate missing evidence is **whether Swift6.4 at the accepted flags emits
all required concrete specializations and statically proven accesses**, especially
recursive semantic visitor/read slots and generated payload callbacks. The current
artifacts cannot prove that future codegen. No fundamental impossibility or needed
contract amendment has been established. If it fails, report the exact residual
call and constraint before corrective2. Changing fixed-domain generic read scopes,
allowing escaped factories, disabling required runtime exclusivity, requiring a new
compiler policy/runtime, or using an alternative profile crosses ADR-036/S13.1/
S15.1 and needs the applicable upstream decision; it is not a local fallback.
