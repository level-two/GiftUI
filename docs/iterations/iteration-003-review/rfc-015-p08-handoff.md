## Pre-code physical design-note checklist

The focused note explains replaceable realization under approved contracts and
must not become authority for a different architecture. It must contain:

- Actual old/new site inventory: reservation/binding, initialized CounterStaticKeys?
  slot, interaction.take, control placement, geometry initialization, every access
  constructor, host/pipeline initializer, measurement/audit, reset and deinitializer.
- For each geometry object and five distinct banks: typed representation, physical
  owner, reserved extent, alignment/padding, initialized-object count/stride, actual
  lifetime, initial role, and stable-address mechanism. Derive actual offsets with
  checked arithmetic when realization chooses them; this handoff supplies none.
- Separate state/control and fixed inventory storage, with no duplicated transaction
  owner or retained old Optional. State every actual constructor temporary and move;
  final-region syntax alone does not establish compiler stack behavior.
- Actual disjoint typed borrowing and common-token construction, including private
  unsafe bridge bounds, no independently borrowed pointer-lifetime substitute,
  Dynamic reference/COW alias exclusion, runtime exclusivity and reentry enforcement.
- Pairwise immutable logical capacities and full retained extents, count/address
  descriptor exchange, preflight provenance checks, serialized infallible commit,
  refusal reset and original physical destruction inventory after repeated swaps.
- Reserved→initialized/idle→active→idle→final-release transitions, exact successful
  prefix unwind and once-only destruction; explicit invalid reinitialize/release paths.
- Cleanup owner at every body return: before host, failed activation, candidate failure,
  successful commit/refusal and normal shutdown; stop/drain and once-only candidate
  resolution, cache ticket pre-quiescence release, pins/registrations, consuming Optional
  retirement, semantic→geometry→Interaction reset and end of all accesses before backing.
- Complete lifetime union through Static/Dynamic supplied/pipeline/coordinator/host/
  retired state and activation span; explicit owned-only workspace path and measurement.
- Evidence plan for each SO criterion, physical owner/address accounting versus role
  accounting, initialization faults/repeated sessions, nested stack/IRQ attribution and
  linked RAM/flash/zero-heap. Name unproved implementation/fit items as unproved.

If exact realization needs a new retained scoped dispatcher, omitted lifetime input,
new storage associated type, disabled exclusivity, duplicated state machine, changed
ownership or limit, stop the affected task for upstream review. Normal typed field
layout/initialization/disjointness realization is SO-02 implementation design work;
its proof is required before acceptance, not a prerequisite to RFC selection.
